## AI 前沿动态

### 1. Teaching Claude why（对齐训练方法论）

> 来源: Anthropic Research | 2026-05-08

Anthropic 以去年 **agentic misalignment** 研究为起点，回顾 Claude 4 时代模型在虚构伦理困境中曾出现极端不当策略等问题，并总结此后安全训练的更新。文章提出四条经验：仅在评测分布上直接训练可压低不当行为但 **OOD 泛化有限**；宪法文档与正面虚构故事等 **远离评测分布** 的数据仍能改善对齐；** demonstrations 往往不够**，让模型解释「为何」某种行为更好、或学习更完整的角色刻画通常更有效；数据 **质量与多样性**（含工具定义等简单增广）持续带来意外收益。团队还介绍了「difficult advice」数据集（用户处于伦理灰色地带、模型提供顾问式回应）用约 **3M tokens** 取得与更大合成 honeypot 集相近的改进且更可能泛化，并讨论宪法文档训练、RL 过程中对齐是否 **持久**，以及 **拓宽安全相关训练环境** 对 honeypot 评测改进速度的影响。

**关键观点**: 对齐不仅是「矫正行为」，更是 **教模型用与你的价值观一致的方式推理**。

🔗 [阅读原文](https://www.anthropic.com/research/teaching-claude-why)

### 2. Scaling Trusted Access for Cyber with GPT‑5.5 and GPT‑5.5‑Cyber

> 来源: OpenAI | 2026-05-07

OpenAI 将 **Trusted Access for Cyber（TAC）** 定义为面向 **已验证防御者** 的身份与信任框架：在持续拦截明显恶意用途的前提下，对已批准用户降低 **基于分类器的误拒**，以支撑漏洞验证、恶意软件分析、检测工程、补丁校验等 **合法防御工作流**。文章区分三档：**默认 GPT‑5.5**、**GPT‑5.5 with TAC**（多数防御场景入口）、以及 **有限预览的 GPT‑5.5‑Cyber**（更敏感、需更强验证与组织级控制的授权红队/渗透测试等场景）。自 **2026-06-01** 起，个体若使用最宽松网络防御能力需启用 **Advanced Account Security**（或组织 SSO 侧等价抗钓鱼认证）。文中同时强调与 **安全厂商、漏洞研究、检测与供应链安全** 伙伴共建「披露—缓解—检测」飞轮，并指向 **Codex Security** 与开源维护者计划等上下游投入。

**关键观点**: 模型网络能力越强，越要用 **身份 + 用途边界 + 账户安全** 把「给防御者的工具」与「滥用渠道」拆开。

🔗 [阅读原文](https://openai.com/index/gpt-5-5-with-trusted-access-for-cyber/)

### 3. 文心 5.1 正式发布（效率、Agent 与后训练管线）

> 来源: 百度 ERNIE Blog | 2026-05-08（文中提及 5 月 9 日 Arena 搜索榜分数）

文心 5.1 继承文心 5.0 知识，通过 **Once-for-All 弹性预训练**（弹性深度/宽度/稀疏度与动态 Top‑k 路由）将总参数约压至 5.0 的 **1/3**、激活约 **1/2**，并称预训练算力约为业界同规模模型的 **6%**。后训练侧强调 **分离式全异步 RL**：以 RL 中控解耦训练、推理、奖励与 agent loop，配合 **FP8 训推一致性** 与 **Rollout Router Replay（R3）** 等降低训推偏差；并提出以 **多教师在线策略蒸馏（MOPD）** 为核心的 **四阶段** 管线（统一 SFT → 并行领域专家 → **OPD** 融合 → 通用在线 RL）以缓解能力跷跷板。官方披露在 τ³-bench、SpreadsheetBench-Verified Agent、AIME26（工具）、GPQA、MMLU-Pro 等基准上的对外叙述，并指向一言官网与飞桨星河体验入口。

**关键观点**: 国产旗舰竞争正从「纯 scaling」转向 **弹性预训练 + Agentic RL 工程 + 多阶段能力融合** 的组合拳。

🔗 [阅读原文](https://ernie.baidu.com/blog/zh/posts/ernie-5.1-0508-release/)

### 4. Computer Environments Elicit General Agentic Intelligence in LLMs（LLM-in-Sandbox）

> 来源: Cheng et al.（人大 GSAI、微软研究院、清华等）| arXiv:2601.16206

工作将计算机虚拟为仅含基础能力的 **代码沙箱**，模型通过 bash、文件编辑与完成信号在多轮中与沙箱交互。实验显示 **无需额外训练** 时，多域前沿模型在数学、物理、化学、生物医学、长上下文与指令遵循等任务上可获得 **约最多 +15.5%（数学）** 等提升，且长上下文场景 token 可降至约 **1/8**。作者将增益归因于三类 **环境激发** 的元能力：外部资源获取、文件系统管理与代码执行验证。进一步提出 **LLM-in-Sandbox-RL**：仅用存放在文件中的非 agentic 数据进行 RL，促使较弱模型从「沙箱不如纯文本」转为显著优于基线，且部分结构化推理可 **内化** 到无环境访问的纯文本推理中。

**关键观点**: **最小通用沙箱** 本身即可作为与模型能力正交的「能力放大器」，为通才 Agent 提供可复现研究底座。

🔗 [阅读原文](https://arxiv.org/abs/2601.16206)  
🔗 [项目页](https://llm-in-sandbox.github.io/)

## AI 工程实践

### 5. Running Codex safely at OpenAI

> 来源: OpenAI | 2026-05-08

OpenAI 说明内部如何在真实工程流中部署 **Codex**：目标是在 **清晰技术边界** 内保持高效，对高风险操作强制 **人工可见**。要点包括：**沙箱 + 审批策略** 联动；**Auto-review** 子代理对低风险操作自动放行以减少打断；**托管网络策略** 默认拒绝宽泛外连、对未知域名要求审批；**规则引擎** 区分日常 shell 命令与高危模式；**托管配置**（云端 requirements、macOS managed preferences 等）保证基线一致；以及面向安全的 **OpenTelemetry** 导出与 **Compliance Platform** 日志，供内部 **AI 安全分诊代理** 结合终端告警解释「用户意图 vs 代理行为」。

**关键观点**: 编码 Agent 的治理 = **策略即代码（沙箱/网络/规则）** + **可审计的代理原生遥测**。

🔗 [阅读原文](https://openai.com/index/running-codex-safely/)

## 趋势总结

1. **对齐研究** 正更多依赖「教价值观与推理链」与 **远离评测分布** 但仍相关的训练信号，而非仅在 honeypot 上拟合。
2. **网络与编码能力** 的下一代产品叙事，普遍绑定 **身份验证、分级授权与合规日志**，OpenAI 在 TAC / Codex 两侧形成互证。
3. **国产旗舰** 开始系统展示 **训推一体 RL 工程**（异步、FP8、路由一致性）与 **多阶段蒸馏–RL** 的组合，效率与 Agent 指标并重。
4. **环境即能力**：LLM-in-Sandbox 类工作提示行业：最小沙箱可能是成本最低的 **通用能力外包层**。
5. **平台侧** 需要将隐私叙事从法务附件升格为 **与模型发布并列** 的用户可控默认体验。
