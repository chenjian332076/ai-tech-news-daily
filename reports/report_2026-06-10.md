### 2. LightningLM 120B：单节点百亿 MoE 训练的操作配方

> 来源: The School of AI / arXiv | 2026-06-08

印度班加罗尔 **The School of AI** 发布 **LightningLM 0.1V**——在 **单台 8×GPU 节点** 端到端训练 **120B 稀疏 MoE**（460 routed experts、top-12 routing、active ~5.93B / stored 118.67B），并公开完整系统报告与代码。

**三大学科**  
| 学科 | 机制 | 效果 |
|------|------|------|
| 可逆性（Reversibility） | 反向传播重构激活而非存储 | 深度/专家增长时 activation memory **保持平坦** |
| 状态保持增长（State-Preserving Growth） | 密集种子 → 5B MoE → 9B MoE → 120B，每阶段从上一阶段权重生长 | 避免 silent failure（看似正常 loss 但 invariant 已破） |
| 单节点经济学（TQP） | 专家权重量化 + 低秩 adapter 承载 optimizer state | 专家路径 optimizer state **削减 ~45×**（2.26B vs 100B+） |

**配套发布**  
- **BrahmicTokenizer-131K**：Indic 文本 token 数 **-26.7%**（Odia **4×+**），英语/代码/math 持平或更优  
- **Kronecker 嵌入**：131K 词表下 embedding 从 ~537M 参数降至 ~33.55M，且 **无需物化 17GB 查找表**  
- 训练 loss 在 120B 规模达 **1.78**（8K context，自 9B 阶段起）

**关键观点**: 这不是 benchmark 论文而是 **系统经验报告**——价值在于公开 growth 操作配方与失败模式目录，证明 frontier-scale 预训练可在 **非 mega-cluster** 条件下完成；对全球 AI 主权与算力民主化叙事有结构性意义。

🔗 [School of AI 公告](https://maharastraportal.in/the-school-of-ai-bangalore-demonstrates-indias-frontier-scale-ai-capability-with-lightninglm-a-120-billion-parameter-language-model/)

### 3. SparDA：解耦稀疏注意力实现长上下文推理加速

> 来源: arXiv (MIT Han Lab 等) | 2026-06

**SparDA（Sparse Decoupled Attention）** 提出将稀疏注意力中的 **Forecast 投影** 与 attention query 解耦——用 Forecast 预测下一层所需 KV block，实现 **lookahead prefetch**，在 CPU→GPU 传输与当前层计算 overlap。

**效率数据（8B 稀疏预训练模型）**  
| 指标 | 提升 |
|------|------|
| 额外参数 | **<0.5%**（仅训练 Forecast 投影，KL 对齐原 selector 分布） |
| Prefill 加速 | 最高 **1.25×** |
| Decode 加速 | 最高 **1.7×**（相对 sparse offload baseline） |
| 单卡吞吐 | 最高 **5.3×**（相对非 offload sparse baseline，因可承载更大 batch） |

在 MiniCPM4.1-8B 与 NOSA-8B 上，精度与 sparse baseline **持平或略优**。

**关键观点**: 长上下文 Agent 的瓶颈正从「算 attention」转向「搬 KV」——SparDA 用 **<0.5% 参数** 的 Forecast head 解决 prefetch 调度，为端侧/单卡长程 Agent 提供可插拔优化路径。

🔗 [arXiv 论文](https://arxiv.org/pdf/2606.04511)

### 5. Perplexity Search as Code：可编程搜索栈替代 MCP 串行调用

> 来源: Perplexity Research | 2026-06-01

Perplexity 发布 **Search as Code (SaC)**——将搜索栈拆解为 **Agentic Search SDK 原子原语**（retrieve、fanout、filter、dedupe、rerank、parse_field 等），由 Agent 在 **安全沙箱** 内生成 Python 编排检索流水线，而非通过 function calling / MCP 串行调用固定 endpoint。

**架构三层**  
1. **Model**：控制面——分解任务、生成检索代码  
2. **Sandbox**：确定性执行（条件分支、异步、并行）  
3. **Agentic Search SDK**：暴露 Perplexity 搜索基础设施的最细粒度原语

**基准表现**  
| Benchmark | SaC | 次优 |
|-----------|-----|------|
| DeepSearchQA | **0.871** | Anthropic Managed Agents 0.815 |
| BrowseComp | **0.805** | OpenAI Responses 0.720 |
| WANDR（wide research） | **0.386** | 次优 0.152（**2.5×**） |

**CVE 案例研究**：追踪 200 个高危 CVE 厂商公告——SaC **100% 准确率**，token **42.9K vs 288.7K（-85%）**；竞品系统 **<25%**。

**关键观点**: SaC 将 RAG 从「调 API 塞 context」升级为「写代码操控检索栈」——filter/rank/dedupe 移出 LLM context 进入确定性代码，直接回应 Agent 时代 **MCP 串行调用 token 膨胀** 痛点；已作为 Perplexity Computer 与 Agent API **默认架构** 上线。

🔗 [Perplexity Research 官方](https://research.perplexity.ai/articles/rethinking-search-as-code-generation)

### 6. JAMEL：新颖性信号驱动的联合 Agent 记忆与探索学习

> 来源: 清华 / 百度 / arXiv | 2026

**JAMEL（Joint Agent Memory and Exploration Learning）** 解决潜记忆缺乏 step-level 监督的核心难题——用 **持久新颖性信号**（GUI 域为 V8 **代码覆盖率**：lines + branches + statements + functions）同时训练 **记忆压缩器** 与 **探索策略**。

**方法要点**  
- 历史 (observation, action) 对压缩为 **单 token 潜记忆**，通过线性 aligner 注入 Qwen2.5-VL-7B 策略模型  
- 24k 样本、**86 个 Web 应用**训练；**10 个 unseen app** 评测（50 步/会话）  
- 覆盖率 baseline **跨 episode 不重置**——自然形成难度递增课程

**结果（ScaleWoB 基准）**  
| 方法 | 累计 coverage reward | Token/步 |
|------|---------------------|----------|
| ReAct-vision (Gemini 3.1 Flash-Lite) | 20.9 | 46,521 |
| ReAct-text | 19.9 | 37,878 |
| **JAMEL-9B** | **20.7** | **2,122** |
| MAI-UI-8B | 8.4 | 5,960 |
| Mobile-Agent-v3.5-8B | 5.9 | 5,864 |

JAMEL 以 **9B 参数** 逼近闭源 Gemini ReAct，token 效率 **17—22×** 于显式历史方案。

**关键观点**: 记忆与探索是 **互依闭环**——探索提供记忆监督，记忆支撑更深探索；代码覆盖率作为 **零标注、确定性、持久** 信号，为长周期 GUI Agent 开辟可扩展训练路径。

### 8. FM Agent Sim-to-Real 统一 MDP 框架

> 来源: ASU / KDD 2026 Blue Sky | 2026

亚利桑那州立大学团队在 KDD 2026 Blue Sky 论文中提出：FM Agent 的部署可靠性问题应被形式化为经典 **sim-to-real gap**，按 MDP 四元组 **Observation / Action / Transition / Reward** 分解——而非当作全新现象重新发明轮子。

**四通道映射示例**  
| MDP 元素 | FM Agent 实例 | 经典缓解 |
|----------|--------------|----------|
| Observation | 多语言 tool call 参数值语言不匹配（中文 query → 英文 API 违规） | Domain randomization |
| Action | 同名干扰 tool、冗余 tool 混淆选择 | Action shielding |
| Transition | API 超时、部分 JSON、非确定性重试 | Transition-level DR |
| Reward | 忽略延迟/费用，过拟合 binary accuracy | Multi-objective / cost-aware reward |

实证：GPT-5 英语→中文 tool call 错误率从 **13.5% → 28.5%**；Qwen3-Next-80B 从 **5.5% → 46.5%**——语义正确但执行无效。

**关键观点**: Agent benchmark leaderboard 分数 ≠ 部署可靠性——将机器人 sim-to-real 成熟框架移植到 FM Agent，可统一 **压力测试词汇表** 并避免碎片化 rediscovery。

🔗 [arXiv 论文](https://arxiv.org/abs/2606.07017)

### 10. NF-CoT：归一化流潜推理保留自回归优势

> 来源: arXiv | 2026-06

**NF-CoT** 用 **TARFlow-style 归一化流** 在 LLM backbone 内建模连续 thought 分布——在保持 **左到右生成、KV cache、可采样、可计算 likelihood** 的前提下，将中间推理移出离散 token 流。

代码生成 benchmark 上 pass rate **超越显式 CoT 与既有 latent reasoning baseline**，且中间推理成本 **显著降低**。

**关键观点**: 潜推理不必牺牲自回归部署优势——NF 提供 exact likelihood 使 **latent space 策略梯度** 成为可能，为「思考不走 token 账单」提供工程可行路径。

### 11. Wall Attention：对角门控替代 RoPE 的长度外推

> 来源: Tilde Research | 2026-06

Tilde Research 发布 **Wall Attention**——将线性 RNN 对角遗忘门推广到 softmax attention，作为 **RoPE 全替代** 的数据依赖位置编码。

**结果**  
- 400M：Muon 与 Aurora 优化器下均优于 RoPE  
- 1B：预训练 **+0.01 nats**，短/长上下文下游均 SOTA  
- 开源 Triton 训练/解码 kernel，decode 速度匹配 FA3

**关键观点**: 多数 PE 变体仅优化长度外推而非预训练收敛——Wall 在 **预训练效率 + 长度外推** 双维度击败 RoPE，且与 GQA/MLA 兼容，具备 production-ready 潜力。
