### 1. Microsoft 披露 Claude Code GitHub Action 凭证窃取漏洞

> 来源: Microsoft Threat Intelligence / Blaze Trends | 2026-06-07

Microsoft 研究人员披露 Anthropic **Claude Code GitHub Action** 存在严重 prompt injection 漏洞——攻击者可在 issue body 或 PR comment 中嵌入恶意指令，诱使 Agent 读取 `/proc/self/environ` 并外泄环境变量，包括高度敏感的 **`ANTHROPIC_API_KEY`**。

**攻击链**  
| 阶段 | 机制 |
|------|------|
| 入口 | 不可信文本（issue/PR comment）被 Agent 读取 |
| 利用 | 恶意 prompt 绕过沙箱，执行未授权 shell 命令 |
| 外泄 | 读取 `/proc/self/environ` 获取 cloud token / API key |
| 影响 | CI/CD pipeline 级凭证泄露，等效于供应链攻击 |

**修复时间线**  
- **4/29**：Microsoft 经 HackerOne 报告 Anthropic  
- **5/5**：Claude Code **v2.1.128** 发布，显式禁止读取 `/proc/self/environ` 等系统文件  
- **6/7**：Microsoft 公开发布威胁分析，呼吁 industry 重新评估 CI/CD Agent 权限模型

**行业共振**  
Microsoft 自身近期亦修补 Semantic Kernel 中的类似 RCE 架构缺陷——**「prompt injection → Agent 有文件/网络权限 → 基础设施级泄露」** 成为 2026 H1 跨 vendor 共性危机。

**关键观点**: 与 6/3 832 账户 MITRE 映射（攻击后移）、6/5 Prompt Injection CI 论文（不可能性）、6/6 RSI 报告（80% AI 写码）形成 **「Agent 产能暴增 ↔ CI/CD 攻击面同步扩大」** 张力——enterprise 部署 coding Agent 的 blocker 从 model capability 转向 **最小权限 + 不可信输入隔离**。

### 2. LegoNE：LLM 发现超越人类专家的 Nash 均衡算法（Nature Communications）

> 来源: Nature Communications / 北京大学北京国际数学研究中心 | 2026-06-04

北京大学 Deng Xiaotie 团队发表 **LegoNE** 框架论文于 Nature Communications——首次实现 LLM 驱动的 **可证明 worst-case 保证** 算法自动发现，突破「AI 只能解实例、不能证定理」的传统边界。

**LegoNE 核心机制**  
- 将专家证明策略编码为 **符号语言**（Python-like 高层描述）  
- 任意候选算法自动编译为 **有限优化问题**，求解即得 approximation bound 证明  
- 与 reasoning LLM 集成：LLM 生成候选 → LegoNE 自动验证 → 反馈迭代

**突破成果**  
| 场景 | 结果 | 对比 |
|------|------|------|
| 二人博弈 ANE | 重发现已知最优多项式时间算法 | 人类研究者耗时 **15 年** 的成果，LLM **数小时** 复现 |
| 三人博弈 ANE | 新算法 bound **0.5+δ** | 超越人类最佳 **0.6+δ**（extension technique 范式上限） |
| 证明意义 | 新算法 **可证超越** extension technique | 人类已知唯一的多人 ANE 设计范式被突破 |

**范式意义**  
论文提出 **「人类定义高层结构 + 机器探索 + 自动形式验证」** 协作范式——人类用符号压缩搜索空间，AI 在约束内发明算法，LegoNE 提供 machine-tractable 证明闭环。

**关键观点**: 与 5/21 Erdős 几何证明、6/2 AlphaProof Nexus 形成 **「AI 数学/算法发现」** 三连击——但 LegoNE 的独特贡献是 **worst-case guarantee 可自动化**，为 frontier lab 的 RSI 叙事提供 **可审计的科学发现** 对照组。

🔗 [Nature Communications 论文](https://www.nature.com/articles/s41467-026-74003-1)  
🔗 [arXiv 预印本](https://arxiv.org/html/2508.11874v1)

### 6. OpenAI Lockdown Mode：确定性出站限制对抗 prompt injection 外泄

> 来源: OpenAI / Simon Willison / Engadget | 2026-06-04

OpenAI 6/4 宣布将 **Lockdown Mode** 扩展至 **全部个人账户**（Free/Go/Plus/Pro）及自助 ChatGPT Business——这是 2 月 Enterprise 首发后的 **consumer 全面开放**。

**Lockdown Mode 机制**  
| 控制 | 行为 |
|------|------|
| 设计哲学 | **确定性** 禁用出站网络能力——非 AI 判断是否安全 |
| 禁用功能 | Live web、Agent Mode、Deep Research、Canvas 联网、live connectors、file downloads |
| Web browsing | 仅限 **cached content**——无 live 网络请求离开 OpenAI 网络 |
| 不禁用 | Memory、file upload、conversation sharing；**Codex 网络访问不受影响** |

**明确边界**  
- Lockdown Mode **不阻止** prompt injection 进入上下文（如 cached web 中的恶意指令）  
- 专注阻断 **出站数据外泄** 的最后一环——Simon Willison 指出这暗示 **默认 ChatGPT 设置对坚定攻击者的数据外泄保护并不充分**

**配套：Elevated Risk 标签**  
- ChatGPT / Atlas / Codex 中对网络相关能力统一标注 **「Elevated Risk」**  
- 用户可见风险说明 + 适用场景指引

**关键观点**: 与 6/7 Claude Code CI/CD 漏洞、5/31 FIDES IFC 防御、6/5 ASSERT 形成 **「确定性出站限制 / 信息流控制 / 策略驱动 eval」** 三层防御栈——2026 H2 enterprise AI 安全采购新增 **「是否支持 Lockdown-equivalent 模式」** 评估项。

### 8. Microsoft CodeAct + Hyperlight：Agent 多步工具调用压缩为单次沙箱执行

> 来源: Microsoft Agent Framework / Build 2026 | 2026-05-31

Build 2026 发布 **CodeAct** 模式——Agent 不再逐步选择工具等待返回，而是 **编写单次 Python 程序** 在沙箱中调用全部工具，经 **Hyperlight micro-VM** 隔离执行。

**性能基准（代表性多步 workload）**  
| 指标 | Traditional tool loop | CodeAct | 改善 |
|------|----------------------|---------|------|
| 端到端延迟 | 27.81s | 13.23s | **-52.4%** |
| Token 消耗 | 6,890 | 2,489 | **-63.9%** |

**Hyperlight 安全模型**  
- 每次 `execute_code` 调用在 **fresh micro-VM** 中运行  
- Guest 启动 **毫秒级**——per-call 强隔离几乎零成本  
- 支持 file mounts、network allow-list、`call_tool(...)` 访问 provider-managed tools  
- Python 包 `agent-framework-hyperlight`（alpha）；.NET `Microsoft.Agents.AI.Hyperlight`

**与 ASSERT/ACS 的关系**  
- ASSERT = policy → eval → runtime control  
- CodeAct = **runtime 执行范式优化**（减少 model turn 数）  
- 二者合并：**更少 turn + 更强隔离 + 可审计 policy** = long-running agent 成本-安全双优化

**关键观点**: CodeAct 将 Agent 优化从 **「选更快模型」** 转向 **「减少 model turn 数」**——与 6/1 SNLP 层并行（-层间延迟）、6/6 KVarN KV 量化（-memory）形成 **「turn / layer / memory」** 三轴推理成本压缩。

### 9. OpenAI API 内联 Moderation Scores：生成请求一站式审核

> 来源: OpenAI API Changelog | 2026-06-04

OpenAI 6/4 在 **Responses API** 与 **Chat Completions API** 中新增 **内联 moderation scores**——开发者在单次 generation 请求中即可同时获得 **输入与输出的 moderation 分类分数**，无需额外调用 Moderation endpoint。

**能力细节**  
- 请求中传入 `moderation` 对象 → 响应含 `moderation_result`  
- 覆盖类别：harassment、hate、sexual、violence、self-harm、illicit 等 **23+ 子类**  
- 每类含 **flagged 状态 + confidence score + applied input types**（text/image）  
- 支持 `omni-moderation-latest` 模型

**工程价值**  
| 场景 | 收益 |
|------|------|
| 应用层过滤 | 基于 score threshold 实时拦截，无需二次 API 调用 |
| 审计合规 | 输入/输出 moderation 证据与 generation log 同源 |
| Agent 流水线 | 多步 Agent 每步 moderation 成本 **减半**（无独立 endpoint） |

**关键观点**: 与 6/5 ASSERT policy-driven eval、6/6 EU 12-field audit trail 形成 **「生成时 moderation + 策略 eval + 决策审计」** 合规三角——IPO 窗口下 **「safety signal 与 generation trace 绑定」** 成为 API 产品设计标配。
