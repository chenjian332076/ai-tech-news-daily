### 2. ARC-AGI-3：交互式 Agent 智能的未饱和基准

> 来源: ARC Prize Foundation / arXiv | 2026-03（2026 年 5 月社区跟进）

**ARC-AGI-3** 将评测从静态网格谜题扩展为 **回合制交互环境**：Agent 在无显式指令下须 **探索、推断目标、建世界模型并规划动作**。环境仅依赖 **Core Knowledge** 先验，经大量人类试玩校准难度；人类 **100%** 可解，而截至 **2026 年 3 月** 前沿 AI 得分 **低于 1%**。评分采用 **RHAE（Relative Human Action Efficiency）**：与人类动作基线对比，惩罚暴力搜索。数据集含 **25** 个公开演示环境、**55** 半私有与 **55** 完全私有环境；公开集刻意与私有集 **OOD**，防止 harness 过拟合。配套开源 [**ARC Harness**](https://github.com/arcprize/arc-agi-3-benchmarking) 支持 `uv run python -m arcagi3.runner` 快速 benchmark。**2026 ARC Prize** 设 ARC-AGI-2 与 ARC-AGI-3 双赛道。

**关键观点**: 当 ARC-AGI-1/2 被 test-time 训练「刷穿」后，社区把「通用 Agent 智能」的残余差距押在 **无语言、需在线探索** 的交互世界上。

🔗 [论文](https://arxiv.org/html/2603.24621v2)  
🔗 [2026 竞赛](https://arcprize.org/competitions/2026/arc-agi-3)  
🔗 [Benchmarking 仓库](https://github.com/arcprize/arc-agi-3-benchmarking/)

### 3. RITE：仅在数学上 Tool-RL，却泛化到物理/商业推理

> 来源: arXiv | 2025-10（2026 年 5 月收录讨论）

论文提出 **RITE（Reinforcement Learning for Interleaved Tool Execution）**：强制 **Plan–Action–Reflection** 交错循环，工具输出即时回灌推理而非线性「想完再调工具」。配合 **Dr. GRPO**（token 级损失聚合 + 重要性采样）缓解长轨迹奖励稀疏；**双分量奖励**（结果 + 格式）与 **在线 rollout 过滤**（通过率 0.1–0.9）构成课程。**仅用数学+代码解释器数据训练** 的 **Qwen2.5-7B** 在 AIME25 达 **36.7%**，在 GPQA/TheoremQA/WebInstruct 等综合 **53.2%**；**32B** 在 AIME24 **71.3%**、WebInstruct **82.3%**，超越 ReTool/SimpleTIR 等同规模基线。作者论证：可迁移的是 **工具调用结构**，而非领域知识本身。

**关键观点**: Agent 工具学习的下一个前沿是 **交错反思式策略**——与「数学专用 SFT」路线相比，结构正确的 RL 更可能买到跨域泛化。

🔗 [论文](https://arxiv.org/html/2510.11184v2)

### 5. Tool-call Reward Model（TRM）：ICLR 2026 细粒度工具调用信用分配

> 来源: OpenReview / ICLR 2026

**TRM** 是专为 **每一次 tool invocation** 打分的过程奖励模型，解决纯 **outcome-only RL** 的粗粒度信用分配（正确工具调用却因最终答案错误被惩罚）。团队在 **10K 样本** 上训练 **3B TRM** 即表现稳健；与 **PPO/GRPO** 集成时采用 refined credit assignment 与 **turn-level advantage**，并防范 **reward hacking**（为避罚而减少工具调用）。在搜索 QA 与 **Python 代码数学** 任务上，TRM 一致优于 outcome-only 方法。

**关键观点**: Agentic RL 的下一层基础设施是 **「按次工具调用」的过程 RM**——与 outcome RM 并列，降低多步 Agent 训练的梯度冲突。

🔗 [OpenReview](https://openreview.net/forum?id=LnBEASInVr)

### 6. Claude Dreaming：Agent 记忆的异步整理与 6× 任务完成率

> 来源: Anthropic Managed Agents API | 2026-05-06（5 月文档完善）

**Dreaming**（研究预览）是 **Managed Agents API** 中的异步作业：读取既有 **memory store** 与最多 **100** 条历史 session 转录，输出 **全新重组 memory store**（合并重复、用最新值替换矛盾项、提炼跨会话模式），**不修改** 输入 store 与原始 transcript。需 beta 头 `managed-agents-2026-04-01` + `dreaming-2026-04-21`；模型限 **claude-opus-4-7** / **claude-sonnet-4-6**。Harvey 在法律起草工作流报告启用后 Agent 任务完成率约 **6×**。与 **Outcomes**（rubric 自评迭代）、**Multi-agent Orchestration** 同属 Code with Claude 2026 基础设施三件套。

**关键观点**: 长程 Agent 的瓶颈正从「单会话上下文」转向 **跨会话记忆 curation**——Dreaming 把「睡了一觉整理笔记」产品化。

🔗 [API 文档](https://platform.claude.com/docs/en/managed-agents/dreams)

## 技术趋势与洞察

### 7. METR：开发者生产力实验因 Agent 普及而「测不准」

> 来源: METR | 2026-02-24（2026 年 5 月行业广泛引用）

METR 更新其 **随机对照开发者生产力** 研究：2025 年 2–6 月数据显示资深开源贡献者用 AI 后任务完成时间 **平均慢 19%**（尽管主观感觉快 20%）——即著名的 **「验证税」**。但 **2025 年 8 月** 启动的跟进实验中，越来越多开发者 **拒绝参与「禁用 AI」条件**（「不愿不用 AI」），且主动只提交「适合 AI 的任务」，使新数据 **无法可靠估计 2026 年真实加速**。在仍参与者的子集上，原队列开发者估得 **-18%**（加速）、新招募者 **-4%**，但作者强调这很可能是 **下界**。METR 将改做 **开发者级随机化、固定任务实验、观测性 GitHub 数据与 Agent eval**。

**关键观点**: 「AI 让工程师更快还是更慢」在 2026 年已无法再用 2025 年的 task-level RCT 回答——选择偏差本身成了方法论前沿。

🔗 [METR 博文](https://metr.org/blog/2026-02-24-uplift-update/)

## 趋势总结

1. **上下文即基础设施**：GPT-5.6 若坐实 150 万 token，将与 SubQ、Gemini 等路线一起，把「整库 RAG」部分内化为模型能力，改写 Agent 记忆架构选型。
2. **Agent 评测进入交互时代**：ARC-AGI-3 证明静态 puzzle 基准已饱和；未饱和的是 **无指令探索 + 动作效率**——未来 leaderboard 将更像游戏 AI 而非 MMLU。
3. **企业采购看治理**：Gartner MQ 把 Codex 与 Cisco 级客户案例绑定，标志编码 Agent 从开发者玩具进入 **CIO 预算品类**。
4. **RL 信用分配细化**：TRM 与 RITE 分别从 **过程奖励** 与 **交错结构** 解决 Tool-Agent 训练稳定性——工具调用正成为可论文化、可复现的子领域。
5. **生产力证据危机**：METR 坦诚 2025 年「变慢 19%」无法外推至 2026——行业需接受：**自选任务 + 拒绝无 AI 条件** 使经典 RCT 失效，测量方法必须升级。
